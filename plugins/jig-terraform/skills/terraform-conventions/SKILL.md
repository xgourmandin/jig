# Terraform / OpenTofu conventions (Jig)

Company-wide defaults, based on the HashiCorp style guide and the Google Cloud and AWS Terraform best-practice guides. A repo's own `.claude/rules/terraform.md` or ADRs in `.archgate/adrs/` override them. Details, examples and rationale: [writing.md](writing.md). For how to split code into modules, stacks and environments, use the `terraform-architecture` skill.

**Binary.** Use `tofu` if the repo has `.opentofu-version` or pins `opentofu` in `mise.toml`, otherwise `terraform`. Never run `apply`, `destroy`, `import` or `state` mutations: CI applies (the guard blocks them). Validate offline: `init -backend=false`, then `validate`. The Stop hook does this for modules you edited; the edit hook runs `fmt` and `tflint`.

**Layout.** One module per directory: `main.tf`, `variables.tf`, `outputs.tf`, `versions.tf` (terraform block: `required_version`, `required_providers`), plus `providers.tf`/`backend.tf` in root modules only, and `locals.tf`/`data.tf` when large. Split `main.tf` by concern (`network.tf`, `iam.tf`) once it grows past ~150 lines, never one file per resource. Local submodules in `modules/<name>/`, examples in `examples/<name>/`, templates as `templates/*.tftpl`, static files in `files/`, scripts Terraform calls in `scripts/`. Every module has a `README.md` (inputs/outputs generated by terraform-docs if the repo uses it).

**Naming.** snake_case for every block label, variable, output and local. Names are singular nouns describing the role, never repeating the type (`aws_s3_bucket.artifacts`, not `aws_s3_bucket.s3_bucket_artifacts`). Use `this` (or `main`) for the single main resource of its type in a module. Numeric inputs carry units (`disk_size_gib`, `timeout_seconds`); booleans are positive (`enable_logging`, not `disable_logging`).

**Block order.** Meta-arguments first (`count`/`for_each`, `provider`), then arguments, then nested blocks, then `lifecycle`, then `depends_on`, separated by blank lines. Data sources sit next to the resources that use them (or in `data.tf`). Comments use `#`.

**Variables.** Every variable has `type` and `description`; order `type`, `description`, `default`, `sensitive`, `nullable`, `validation`. Defaults only for environment-independent values; environment-specific ones (account, project, CIDRs) have none. Expose a variable only for a concrete need to vary it: adding one with a default is backward compatible, removing one is breaking. Group related settings in an `object({...})` with `optional()` attributes rather than many loose variables. Use `validation` for constrained inputs. Secrets: `sensitive = true`, never a default.

**Outputs.** Every output has a `description`. Output resource attributes, never pass input variables straight through (that breaks the dependency graph). Reusable modules expose at least one output per resource (ids/ARNs) so callers can depend on them.

**Expressions.** Keep them readable: name intermediate values in `locals`, no nested ternaries, `dynamic` blocks only when the block count really varies. Use `locals` sparingly for repeated literals, not as a second variable layer. Prefer attachment resources (`aws_security_group_rule`, `aws_iam_role_policy_attachment`) over inline blocks when both exist, and don't mix the two for the same object.

**Iteration.** `for_each` over maps/sets with stable, meaningful keys for multiple instances; `count` only for 0/1 toggles (`count = var.enable_x ? 1 : 0`). Don't key `for_each` on values unknown until apply.

**Dependencies.** Rely on implicit dependencies by referencing attributes (prefer computed ones like `id`/`arn` over inputs like `name`). `depends_on` only for hidden dependencies, with a comment saying why.

**Providers and versions.** Child modules never configure providers or backends; they declare `required_providers` with minimum versions (`>=`). Root modules pin `required_version` and providers with `~>`, and commit `.terraform.lock.hcl`. Pin module sources to a release tag or registry version (a commit SHA for third-party git modules), never a branch. Set common tags/labels once (e.g. AWS `default_tags` in the root provider) and expose a `tags`/`labels` map (default `{}`) in modules.

**Secrets.** Never hardcode secrets or commit `.tfvars` that hold them. Read them at apply time from a secrets manager; on Terraform ≥ 1.11 / OpenTofu ≥ 1.11 prefer ephemeral resources and write-only arguments (`*_wo`) so they never reach state or plan. Avoid resources that store key material in state (`tls_private_key`, access keys) unless there is no alternative. Remember `sensitive` only hides values in output; state still holds them.

**Safety.** Stateful resources (databases, buckets, KMS keys, DNS zones) get `lifecycle { prevent_destroy = true }` and the provider's deletion protection in production roots. Renames and moves into modules use `moved` blocks; adopting existing infra uses `import` blocks; dropping from management uses `removed` blocks, never state commands. No `0.0.0.0/0` ingress, public buckets, or wildcard IAM actions/resources without an explicit comment explaining why. Use `check` blocks or `precondition`/`postcondition` for assumptions a plan should verify. Avoid provisioners and `local-exec`; if unavoidable, document why.

**Tests.** Reusable modules get `terraform test` / `tofu test` files (`tests/*.tftest.hcl`), plan-only (`command = plan`) with mocked providers where possible, since sessions have no cloud credentials.

**Enforced rules (ADRs).** `archgate check` and tflint hold the line mechanically; read the ADR before arguing with a failure (`archgate adr show <ID>`). TF-001 pin module sources; TF-002 no `provider`/`backend` blocks in child modules (under `modules/`); TF-003 the shared `.tflint.hcl` (naming, documented/typed variables and outputs, standard module files); TF-006 root modules commit `.terraform.lock.hcl`; TF-007 stateful resources in production roots set `prevent_destroy = true`; TF-009 no secret values in `.tfvars`/`.tf`, secret-named variables are `sensitive` with no default. A justified exception is `# archgate-ignore TF-00X/<rule-id> <reason>` on the line before the flagged line (the block start for TF-002/006/007, the variable block or the line for TF-009); the reason is required.

**Finding things.** Use the LSP (go to definition/references on `module.x`, `var.y`) before grepping. Use registry docs (terraform MCP server, if enabled) for provider arguments instead of guessing.
